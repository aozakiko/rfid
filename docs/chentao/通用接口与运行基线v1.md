# 通用任务与协议接口 v1

> 版本：`generic-v1`  
> 适用范围：软件仿真、协议适配、配置化基准和可追溯候选记录。

## 1. 设计原则

1. 统计协议继续复用 `stat_protocols/contracts.py`，不另造重复结果模型。
2. 传统 `IProtocol.execute(...)` 通过适配器转换，不强迫历史协议伪造通信成本。
3. `custom_task` 只验证执行和输出契约，不生成业务准确率。
4. LLM 生成的自由 Python 在独立子进程中执行；受限 JSON 候选继续走白名单编译。
5. Pareto 按相同 task、distribution、size、扰动和 split 比较。

## 2. 任务画像接口

模块：`code_add/generic_tasks/`

`TaskProfile` 的语义范围：

| semantic_scope | 含义 | 可报告指标 |
|---|---|---|
| `statistical_metric` | 有统一真值和误差指标 | error / precision / recall / F1 |
| `legacy_truth` | 使用历史场景或集合真值 | 集合指标或历史语义结果 |
| `execution_and_output_contract` | 仅验证可执行和输出契约 | `not_available`，不得写 accuracy |

内置画像：

- `mean_estimation -> mean`
- `variance_estimation -> variance`
- `cardinality_estimation -> cardinality`
- `top_k -> top_k`
- `mode_query -> legacy_mode_query`
- `median_quantile -> legacy_median_quantile`
- `missing_stocktaking -> legacy_missing_stocktaking`
- `custom_task -> custom_task`（不进入统计 accuracy）

关键 API：

```python
from generic_tasks import get_profile, list_profiles, resolve_canonical_tasks, validate_profile_id
```

## 3. 协议适配接口

模块：`code_add/generic_protocol/`

统一入口：

```python
run_many(tags, spec, context=None) -> dict[str, RunResult]
```

实现：

- `StatisticsProtocolAdapter`：包装 `stat_protocols` 协议，保留通信计数。
- `LegacyProtocolAdapter`：包装 `IProtocol.execute()`。
- `run_protocol_file(...)`：在独立 Python 子进程中运行协议文件并返回 `RunResult`。

遗留结果规则：

- `estimated_values -> estimate`
- `metric -> metadata`
- `verification_data -> metadata`
- `execution_time -> cpu_time_ms`
- 无真实通信事件时 `cost_status="missing"`，禁止进入通信 Pareto。

## 4. 候选记录

模块：`code_add/generic_protocol/candidate.py`

统一字段：

```text
candidate_id
protocol_name
candidate_type
parents
task_profile
genotype
prompt_hash
response_hash
model
source_hash
validation_result
benchmark_result
status
```

`ai_protocol_optimizer.py` 生成自由 Python 候选时会写入 `<协议名>.candidate.json`。候选记录不包含 API Key。

## 5. 配置化 benchmark

模块：`code_add/benchmark/run_config.py`

配置示例：`code_add/benchmark/configs/smoke.json`。

配置字段：

```text
name, profiles, protocols, distributions, sizes, seeds,
output_dir, price_min, price_max,
missing_rate, noise_rate, extreme_rate, split
```

输出：

- `results.json`
- `summary.csv`
- `profile_support.json`
- `manifest.json`

manifest 区分：

- `start_commit`
- `experiment_generation_commit`
- `release_commit`
- `git_dirty`

## 6. 一键验证

```powershell
cd code_add
python -m tools.verify
```

该命令执行：

1. Python 语法编译；
2. 全量 unittest；
3. 临时目录 smoke benchmark。

## 7. 非目标

本接口不证明硬件时延、EPC C1G2 物理层、信息隔离、隐私保护或完整 LLM 进化质量。这些能力必须通过独立实验和硬件/安全验证补充。
