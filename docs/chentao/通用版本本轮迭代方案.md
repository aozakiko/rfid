> 用途：供本轮负责人直接执行和后续成员交接。  
> 编制日期：2026-10-30（Asia/Shanghai）  
> 建议版本代号：`generic-v1`  
> 基线提交：`34bca80`（上一位同学迭代完成后的当前 `main`）  
> 本轮目标：把目前“统计协议专项原型”收敛为可持续迭代、可复现、便于结项的通用版本。

## 0. 先给结论

本轮不要继续堆叠新的统计算法或重新做大页面，而应完成一次“平台通用化收敛”：

> **把现有统计协议、传统 RFID 协议、任务画像、AI 候选、实验运行和交付证据统一到一套通用接口、配置和运行入口上。**

本轮完成后，项目应达到三个效果：

1. **换任务不改核心**：新增一个任务画像，通过注册表/配置声明，不需要修改 Web、实验和验证核心。
2. **换协议不改实验**：传统 `IProtocol` 协议和 `stat_protocols` 协议都通过同一适配层进入基准测试。
3. **换成员不丢上下文**：下一位同学可以通过一条验证命令、一个运行配置、一份交接文档继续迭代。

本轮结束后的状态应描述为：

> **通用 RFID 协议实验平台 v1：支持任务画像、协议插件、统一评价、配置化实验、可追溯产物和安全执行边界。**

它不是最终的“完整进化算法成果”，而是让后续算法实验能稳定叠加的通用底座。

> **通用边界说明**：这里的“通用”指任务、协议、实验和交付机制可以扩展，不表示当前算法已经覆盖任意 RFID 业务、连续属性、多属性或硬件物理层。算法适用范围仍应在结项材料中如实限定。

### 1.2 原始版本 V0：原来是什么样

原始版本已经形成了“场景资产 + LLM 生成 + 验证 + 迭代 + 实验 + Web”的主流程，核心文件包括：

- `code_add/base.py`：`Tag`、`Frame`、`IProtocol`；
- `code_add/ai_protocol_optimizer.py`：父代读取、Prompt、生成、修复、验证；
- `code_add/Validator.py`：物理约束；
- `code_add/Test.py`：协议批量测试；
- `code_add/course_project/web_app.py`：Web API 和工作台；
- `code_add/course_project/static/`：无构建前端。

这一版的优点是：

- 已经有可运行平台，不是概念稿；
- 有大量历史协议、Prompt 和实验产物；
- 能进行 LLM 代码生成和基础验证；
- 适合继续做算法实验。

但原始版本的“通用性”不足：

- `IProtocol.execute(tags, price_min, price_max)` 基本面向价格众数；
- 任务画像主要存在于 Prompt 文本，验证逻辑与任务语义没有完全统一；
- 实验主要输出 `pass_rate` 和模拟时间；
- 随机种子、哈希和结果统计不够稳定；
- LLM 生成的自由 Python 缺少安全运行边界。

### 1.3 上一同学迭代版 V0.1：现在是什么样

上一同学从 `f3e228b` 到 `34bca80`，新增了以下工作：

1. **AI 网关配置通用化**  
   可在 Web 页面配置 API URL、API Key、模型名，并支持 Chat Completions / Responses。

2. **任意自定义任务画像**  
   不再局限于固定任务名，可输入自定义任务描述并进入生成 Prompt。

3. **统计协议与统一通信计数**  
   新增 `code_add/stat_protocols/`，实现均值、方差、基数、Top-k 的共享匿名直方图协议、单任务协议、串行协议、随机控制和受限 LLM 候选。

4. **可复现实验基准**  
   新增 `code_add/benchmark/`，统一数据生成、seed、通信成本、误差、Pareto、盲测和消融。

5. **统计实验交付证据**  
   新增 `code_add/Experiments/stat_protocols/`，包含主实验、消融、共享对比、敏感度、鲁棒性、盲测、机制表、假设表、运行清单、CSV/JSON/PNG/PDF 和真实 Pixel 候选证据。

6. **统计证据看板**  
   Web 端新增统计基准视图，可查看任务、分布、规模、误差、通信、逐 seed 结果和原始产物。

7. **测试扩展**  
   当前执行 `python -m unittest course_project.test_statistics_service course_project.test_stat_protocols course_project.test_ai_configuration course_project.test_infrastructure course_project.test_course_project -v`，共 56 项测试通过。

这一版已经是“统计协议专项版”，但距离“通用版本”仍有 6 个结构性问题：

| 问题 | 当前表现 | 对轮流迭代/结项的影响 |
|---|---|---|
| 两套协议运行接口 | 传统协议用 `execute()`，统计协议用 `run_many()` | 后续每个算法都要写两套适配 |
| 任务定义分散 | `TaskSpec`、`TASK_GUIDANCE`、Web 自定义任务和验证逻辑分散 | 新任务容易出现“Prompt 支持但基准不支持” |
| 基准入口固定 | `benchmark.suite` 的任务、协议和实验组合写在代码中 | 每次改实验都要改核心脚本 |
| 候选格式不统一 | 传统 Python 候选与统计 JSON 候选记录方式不同 | AI 生成结果无法统一追溯 |
| 运行边界不统一 | 统计候选是受限算子，但传统自由 Python 仍需谨慎执行 | 通用平台不应依赖成员自觉保证安全 |
| 交付与交接不够标准化 | README、实验报告、截图很多，但版本边界和交接模板未固化 | 三人轮流时容易重复劳动或改错文件 |

## 2. 本轮“通用版本”的定义

### 2.1 本轮要交付什么

本轮完成后的 `generic-v1` 应包含以下 8 个交付件：

1. **通用任务画像注册表**  
   一个任务画像由 ID、标题、输入类型、输出类型、真值计算、评价指标、支持能力和 Prompt 指导组成。

2. **通用协议适配接口**  
   统一为：

   ```text
   run_many(tags, task_spec, context) -> dict[task_name, RunResult]
   ```

   传统 `IProtocol` 通过适配器转换；`stat_protocols` 直接实现该接口。

3. **配置化实验入口**  
   使用 JSON 配置声明任务、协议、分布、规模、seed、重复次数、输出目录，而不是改 Python 代码。

4. **统一候选与 provenance 记录**  
   所有候选至少记录：candidate_id、protocol_name、candidate_type、parents、task_profile、genotype、prompt_hash、response_hash、model、validation_result、benchmark_result、status、source_hash。AI 生成的 `legacy_python` 候选和受限 `stat_operator_json` 候选都应进入同一候选清单、manifest 和实验入口。

5. **安全执行边界**  
   传统自由 Python 协议在独立子进程中执行，限制运行时间、输出和异常；统计 JSON 候选继续保持白名单编译，不执行任意代码。

6. **一键验证与运行入口**  
   至少提供：

   ```powershell
   python -m tools.verify
   python -m benchmark.run_config --config benchmark/configs/smoke.json
   python -m course_project.web_app --host 127.0.0.1 --port 8765
   ```

7. **版本演进与交接材料**  
   新增版本说明、迭代交接模板、结项证据索引和本轮完成记录。

8. **不破坏现有成果**  
   现有 56 项测试必须继续通过；现有统计实验和真实候选证据不得被删除或手工改写。

### 2.2 本轮明确不做

以下内容留给后续轮次，不在本轮强行完成：

- 不重写为 Vue、FastAPI 或微服务；
- 不接入真实 RFID 读写器和硬件；
- 不宣称真实射频时延、能耗或隐私证明；
- 不完成完整 NSGA-II / 进化搜索算法；
- 不追求更多统计任务而牺牲接口稳定；
- 不删除已有失败结果或负结果；
- 不进行 Git 历史重写；
- 不让本轮变成“改 UI 样式”专项。

## W2：统一协议适配层

### 任务

建议新增：

```text
code_add/generic_protocol/
├─ __init__.py
├─ base.py
├─ legacy_adapter.py
├─ statistics_adapter.py
└─ registry.py
```

统一接口：

```python
def run_many(tags, spec, context) -> dict[str, RunResult]
```

### 适配规则

1. **统计协议适配器**  
   直接包装 `stat_protocols.protocols`，保留通信计数和 metadata。

2. **传统协议适配器**  
   调用现有 `IProtocol.execute()`，将：

   ```text
   estimated_values -> estimate
   metric -> metadata
   verification_data -> metadata
   execution_time -> cpu_time_ms
   ```

   转换为统一 `RunResult`。

3. **成本缺失规则**  
   传统协议如果 `verification_data` 没有真实通信事件，只能标记 `cost_status=missing`，可以报告执行/语义结果，但不得用 0 或估算值进入通信 Pareto。

4. **能力声明**  
   每个协议声明支持的任务，例如：

   ```text
   supports = {mean, variance, cardinality, top_k}
   ```

   不支持的任务必须返回 `unsupported_task`，不能误判为失败。

5. **协议注册表**  
   后续成员添加协议时，只需注册 adapter，不改实验 runner。

### 验收

- 一个传统协议和一个统计协议能通过同一 runner 运行；
- 不支持任务有明确错误；
- `RunResult` 字段不因协议类型不同而缺失；
- 现有统计协议行为保持不变。

## 6. 验收测试设计

## 6.1 必须新增的测试

1. 新任务画像可通过注册表加载；
2. 未注册任务返回明确错误；
3. `custom_text` 不返回伪造准确率；
4. Pareto 不混合不同分布、规模、扰动或 split；
5. 传统 `IProtocol` 能转换为 `RunResult`；
6. 无通信事件的遗留协议不会进入通信 Pareto；
7. 统计协议通过统一接口运行结果不变；
8. 协议不支持任务时不误判为执行失败；
9. smoke 配置可完整运行；
10. manifest 包含配置 hash、命令、提交号、dirty 状态和 seed；
11. 无效候选不会执行；
12. 自由 Python 超时/异常不影响主进程；
13. provenance 字段缺失会被拒绝；
14. 结果包含失败行和失败原因。

## 6.2 最终命令

```powershell
cd code_add
python -m py_compile course_project\web_app.py benchmark\run_config.py generic_tasks\registry.py generic_protocol\legacy_adapter.py
python -m unittest course_project.test_statistics_service course_project.test_stat_protocols course_project.test_ai_configuration course_project.test_infrastructure course_project.test_course_project course_project.test_generic_contracts course_project.test_run_config -v
python -m benchmark.run_config --config benchmark\configs\smoke.json
python -m tools.verify
```

## 6.3 完成定义

必须同时满足：

- 现有 56 项测试继续通过；
- 新增通用接口测试通过；
- smoke 实验能够一条命令重跑；
- 传统协议和统计协议走同一实验入口；

## 8. 风险与回退

| 风险 | 预警信号 | 回退方案 |
|---|---|---|
| 接口过度抽象 | 一个简单任务需要写很多配置 | 保留默认 profile，抽象只覆盖实际两类协议 |
| 通用化破坏统计实验 | 统计结果字段变化、测试失败 | `stat_protocols` 保持兼容，不改原算法 |
| 子进程执行过慢 | smoke 超过 3 分钟 | 缩小默认 smoke，不减少最终实验 |
| 传统协议转换不准 | verification_data 无法映射 | metadata 保留原始字段，不强转错误指标 |
| 自定义任务能力夸大 | 任意文本被算作准确任务 | 明确 `exploratory`，不输出 accuracy |
| 文档过多难维护 | README、报告、交接互相矛盾 | README 只保留入口，细节进入版本/交接文档 |
| 大产物拖慢仓库 | JSON 超过 10 MB、克隆变慢 | 本轮可先只压缩新产物；历史文件不做破坏性删除 |
| manifest 与最终提交不一致 | 当前 manifest 的 revision 是 `d197452`，HEAD 是 `34bca80` | 区分实验生成提交和 release 提交；最终 release 前重新生成校验 manifest，并明确 SHA-256 的字节/换行口径 |
| 三人合并冲突 | 同时改 `web_app.py`/契约 | 目录所有权和小提交；共享接口一次只由一人改 |
