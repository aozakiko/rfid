# 平台通信优化与独立验证迭代记录

日期：2026-11-03。

本轮继续围绕“基于大模型的 RFID 射频识别通讯协议自优化研究平台”完善平台开发。中期报告是需求主线，参考论文用于借鉴自动生成、验证、反馈和搜索方法。

## 1. 本轮补齐的闭环

选择统计任务与父代 → 模型生成或修复读写器算法 → 子进程隔离与语义验证 → 固定开发集评价 → 在精度约束下选择通信成本较低的候选 → 更新下一轮父代 → 搜索停止 → 冻结选中候选与初始基线 → 使用另一组种子验证并检查数据重叠 → 保存逐次证据。

此前只有质量选择，不能从候选自报时间推断通信收益。本轮新增平台拥有的匿名信道，使生成候选可以参与可信的软件通信成本比较。旧接口继续用于兼容验证和质量探索。

## 2. 平台计量的匿名通信接口

候选可以实现以下入口：

~~~python
from base import IProtocol

class MyReader(IProtocol):
    def execute_channel(self, channel, price_min, price_max):
        observation = channel.observe(round_index=0, slots_per_value=256)
        counts = observation["counts"]
        total = sum(counts)
        return [sum((price_min + i) * n for i, n in enumerate(counts)) / total] if total else []
~~~

- 读写器只获得信道和公开属性范围，不接收 Tag 列表、标签 ID、真实属性或任务真值。
- counts 是匿名 OR 占用观测反演的频数估计，不是真实频数；variance 是不确定度启发量，saturated_bins 表示饱和属性桶数量。
- slots_per_value 为 2～32768，round_index 为 0～1000000；每次执行最多调用 128 次观测。
- 重复调用同一观测仍然计费，不能利用缓存免费获取通信事件。
- reader_bits、tag_bits、slots、frames、rounds 由平台累计。候选自报计数、成本来源或耗时均不能覆盖它。
- 此入口只开放 math、from base import IProtocol 和 __future__ 导入。提供隔离的数学模块和基础类，避免候选通过修改共享 numpy 函数捕获信道内部标签。可使用内置列表、循环和运算。
- 传统 execute(tags, low, high) 继续兼容，其通信值只作为自报诊断，不能取得通信成本排名资格。

软件模型 ID：histogram_or_v1_slot001。单次观测 reader_bits=160、tag_bits=参与标签数、slots=属性域大小×slots_per_value、frames=1、rounds=1。

模拟成本 = reader_bits×0.025 + tag_bits×0.4 + slots×0.001 + frames×30，单位为模拟 ms。空闲时隙项使不同帧布局的占用成本可比较。参数随逐次证据记录，不代表真实射频时间或 EPC 协议实现。

新增 base_protocol/MeasuredHistogramMean.py 和 MeasuredHistogramMode.py，可直接用于验证、比较或作为生成父代。估计仍受碰撞、饱和和近似并列影响，不保证对全部场景都通过语义验证。

## 3. 选择规则

| 目标 | 规则 |
| --- | --- |
| 仅任务质量 | 先比较完整语义通过率，再比较集合 F1 或标量误差质量分 |
| 精度达标后降低模拟通信成本 | 先选择严格隔离、输出与执行门槛通过、具有平台通信计量且达到最低通过率的候选，再按平均通信成本排序；相同成本比较质量 |

默认最低通过率为 1，表示开发集每次都通过配置的语义误差门槛。它不是平均准确率，也不是总体泛化概率。

未达标或只有自报成本的候选可以作为探索父代，但不会冒充通信优化成功。开发数据哈希必须一致，通信模型必须相同，才能比较；相同分数保留原父代。

## 4. 冻结与独立验证

搜索结束才确定赢家。基线是搜索开始时按相同目标选出的初始父代，不是事后挑选最差对照。

平台冻结赢家、基线、生成器和配置，先写出 holdout/selection.json，再执行验证。验证起始 seed 为开发 seed+100000，沿用相同任务与规模。检查实际数据哈希是否与开发集重叠，以及赢家与基线是否使用相同数据。

数据重叠、执行次数不完整或比较数据不一致时，结果为 independence_not_established。不能只换 seed 就宣称独立验证。只有两候选都满足语义要求，成本来源和模型一致时，才输出模拟通信成本降低比例。验证结果不进入后续 Prompt，不改变已经冻结的本轮选择。

这是同一场景生成器下的独立样本验证。跨分布、跨规模、缺失与噪声等更广泛泛化仍通过鲁棒性基准另外研究。

## 5. 停止条件与运行预算

| 参数 | 含义 |
| --- | --- |
| iterations | 最大生成轮数 |
| max_model_requests | 最大实际模型 HTTP 请求数，包含修复、网络重试和接口回退 |
| max_wall_seconds | 时间预算，按阶段检查；候选逐次执行使用剩余时间 |
| no_improvement_rounds | 连续无改进达到指定轮数停止，0 为关闭 |
| target_communication_cost_ms | 精度达标且模拟成本达到目标时停止，0 为关闭 |

运行记录保存实际请求数、耗时、停止原因和已完成轮次。预算耗尽保留已生成候选和父代评价。生成中途停止的尝试记录为未参与选择。

预算与用户停止采用协作式控制：网络请求使用剩余 socket timeout，候选执行使用剩余子进程 timeout。这不是操作系统级绝对截止时间；场景生成、退避、磁盘写入和当前操作收尾可能跨过预算边界。

## 6. 后台任务生命周期

- GET /api/selfopt/jobs：查询持久化任务历史。
- POST /api/selfopt/job/cancel，正文包含 id：停止排队任务，或请求运行任务在阶段边界停止。
- POST /api/selfopt/job/retry：重新运行失败、停止或中断的 AI/迭代任务，使用新的名称/前缀和当前页面模型凭据。
- 重试是重新运行完整配置，不是恢复某一失败阶段；不会覆盖已有候选。
- 历史存储在 course_project/outputs/background_jobs.json。服务重启后未完成任务标记 interrupted，不自动重发模型请求。
- 页面支持继续查看进度、查看保存结果、停止当前迭代和使用新名称重新运行。所有轮询器识别 cancelled/interrupted 终态。
- 快照递归剔除凭据字段，清理日志/结果中的本次请求密钥。真实模型重试需要页面当前的 URL、Key 和模型配置。
