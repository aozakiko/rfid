# 候选评测与前后端闭环完善记录

日期：2026-11-03

本轮围绕“基于大模型的 RFID 射频识别通讯协议自优化研究平台”，完成此前高、中高优先级的六项工程改进。工作重点是连接已有生成、演化、验证和实验能力，让平台能够使用确定版本的协议完成可追溯的评测。

## 1. 统一候选版本库与评测入口

新增“候选评测”页面和 `course_project/research_service.py`。

- Python 协议、统计 JSON 算子统一登记，记录类型、任务、场景、原始路径、源码 SHA-256 和来源。
- 候选 ID 由类型、场景、任务、名称和内容共同确定；同名文件修改后产生新版本，原快照保留。
- 登记后的验证读取冻结快照；每次跨场景实验再次冻结运行源码和配置，并核验完整性。
- 候选损坏时显示完整性问题，禁止使用该版本发起正常评测。
- Python 和 JSON 分别调用严格 Python 信道引擎与既有统计算子流水线。两种成本模型不混合排名。

登记任务表示使用者选择的目标，并不保证该协议能够正确完成任务；实际输出仍由严格验证判定。

## 2. 长任务进入后台并可停止

新增异步验证、异步场景实验接口。Vue 验证和敏感度/绘图操作改为提交后台任务，展示阶段、日志、进度和停止操作。

新增 `task_process.py`，供配置实验、统计流水线、基准套件和场景实验共享：

- 不依赖子进程输出才能响应取消，静默运行的任务也能被停止。
- 支持时间预算、输出上限与已产生输出的部分结果保存。
- 取消或超时时终止该任务启动的进程树，避免实验子进程继续执行。
- 配置实验、报告重建、流水线和套件在排队时取消，也会释放预留的统计实验锁。
- 失败或未完成实验的结果不会获得正式比较资格。

Python 单协议验证在每次执行之间检查取消；正在执行的协议受单次超时约束。模型请求仍采用已有的请求预算和剩余超时，取消在工作流边界生效，并正确显示为“已停止”。

## 3. 冻结赢家进入跨场景验证与盲测

单次真实生成会登记产生的协议；自动迭代返回冻结赢家与初始基线的版本 ID。关闭搜索后的即时独立验证，也保留赢家，便于从页面转入后续实验。

Python 评测支持：

- 六种已有数据分布；不同标签规模；缺失、噪声和异常扰动。
- 独立验证与盲测使用互斥 Seeds，进一步检查实际输入的数据哈希。
- 同一组合中的候选使用相同输入；任务真值与通信计量由平台计算。
- 记录每次原始结果、失败原因、数据哈希、实际冻结源码和评测配置。
- 验证输入与已记录搜索/普通验证输入重叠时，标记并排除对应结果；盲测还检查与本次验证输入的重叠。
- 来源历史不完整、静态拒绝、执行失败或实验未完成时，不宣称已经建立独立性。

普通验证也会保存其对应版本与已暴露数据哈希。导入源码的未知历史不会因此被改写为“已知”。独立性结论只针对已记录的历史，不代表可以证明未记录的人工作业没有使用过相同数据。

这些实验发生在赢家确定之后，结果不会回传给已结束的搜索，也不会重新选择该轮赢家。

统计 JSON 候选经统一入口进入原有“开发 → 验证 → 缺失/噪声/异常 → 盲测 → 双次复现”流水线，与内置基线比较。该引擎使用既有统计任务精度准则，页面不展示实际不会生效的 Python 精度选项。

## 4. 页面之间保留候选上下文

- 协议设计、自动迭代、验证结果和版本库提供“验证此候选”“加入对照实验”。
- 路由携带冻结候选、任务、场景以及可用的对照基线。
- 进入验证页面后显示正在验证的冻结版本；手动修改场景、协议或任务后恢复为当前源码验证。
- 统计 JSON 生成/导入后可以直接进入其评测入口。
- 历史 Python 评测可以通过 `/#/research?run=<运行ID>` 定位；统计流水线通过实验页查询参数定位。

## 5. 结果直接展示可读结论

- 自动迭代展示停止原因、独立验证状态、基线降低比例和子代通信成本趋势。
- 候选评测展示验证/盲测切换、场景成本曲线、通过率、Wilson 95% 置信区间、同场景前沿和排除原因。
- 成本降低比例仅在基线与候选的任务、场景、输入哈希、信道模型和质量门槛一致时计算。
- 每次实验导出 `summary.csv`、`summary.json`、逐次 `results.json`、冻结配置、源码和完整性清单。
- 历史读取重新审计产物；文件被修改或实验未完成时，前端结果撤销比较资格和收益比例。

区间对应通过率；通信成本为软件信道模型的模拟 ms。样本很少时，通过率区间会较宽。页面显示的相对基线收益是该次已配置实验的描述结果，不能替代更大样本的研究结论。

## 6. 能力与错误契约

`GET /api/research/capabilities` 提供候选类型、任务、分布、评测引擎、通信模型与运行上限。

HTTP 兼容原有 `error` 字符串，并增加 `error_info`：`code`、`stage`、`message`、`suggestion`、`retryable`、`request_id`。后台失败采用同一结构。Vue 显示失败阶段、处理建议和编号，保留通用错误提示；公开任务快照继续递归移除模型密钥。

| 接口 | 用途 |

| `GET /api/research/capabilities` | 支持能力和上限 |

| `POST /api/selfopt/experiments-async` | 后台场景实验与绘图 |

原同步接口保留；进度和取消继续使用 `/api/selfopt/job`、`/api/selfopt/job/cancel`。

## 启动与数据位置

在 `E:\RFID\rfid\code_add` 中执行：

```powershell
..\.venv\Scripts\python.exe -m course_project.web_app --host 127.0.0.1 --port 8765
```

前端已构建时访问 <http://127.0.0.1:8765/#/research>。版本库及 Python 评测保存于 `code_add/course_project/outputs/research/`，验证任务证据位于 `outputs/validation_tasks/`；统计引擎继续使用原有 `Experiments/stat_protocols/` 数据位置。

Web Python 评测最多 6 个版本、每个分组 10 个 Seeds、3 个规模、4 组扰动、240 个候选/场景/种子组合。较大研究实验可通过既有 CLI 分批开展。原统计流水线包含额外的扰动与复现阶段，采用自己的既有执行上限。
