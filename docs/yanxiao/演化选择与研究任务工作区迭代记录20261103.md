# 演化选择与研究任务工作区迭代记录

日期：2026-11-03

本轮围绕“基于大模型的 RFID 射频识别通讯协议自优化研究平台开发”完善两个能力：使演化种群按可审查的质量、成本和多样性规则选择；使一次研究的配置、源码、候选和验证评测归属于同一个工作区。

实施前已提交当前 Vue 前端与冻结候选评测版本，提交为 `4284944`。本轮新增代码与文档另作后续提交；本地实验数据、虚拟环境、数据库、运行输出及无关文档改动均排除在提交外。

## 一、演化选择

原有 `quality_only` 和 `precision_constrained_cost` 保持可用，新增 `pareto_diversity`，在自动迭代页和研究任务页均可选择。研究任务新建时默认使用 Pareto 策略。

| 环节 | 本轮规则 |
| --- | --- |
| 可比性 | 候选必须使用相同开发集数据摘要；成本选择要求相同信道模型，否则拒绝比较 |
| 前沿资格 | 验证可排名、通信成本经平台计量、语义通过率达到配置门槛 |
| 优化方向 | 最大化语义通过率、最大化任务质量、最小化模拟通信成本 |
| 种群保留 | 非支配分层；同层按归一化拥挤度优先保留稀疏区域，相同条件优先现有父代 |
| 结构去重 | AST 规范化后忽略格式、注释、docstring 和候选类名，避免只改名的复制品占满种群 |
| 不达标候选 | 有运行证据但精度不足、或只有自报成本的候选可补位探索，不进入达标前沿 |
| 验证失败 | 新失败子代不得晋升；必要时保留现有源码父代作为明确标注的未排名探索入口 |
| 唯一父代 | 去重只剩一个父代时，允许其自身参与变异，避免空配对导致迭代失败 |
| 代表赢家 | 独立验证前固定；有达标前沿时取前沿最低计量成本，成本相同按质量打破平局 |
| 停滞判断 | 同时检查代表表现和前沿目标向量变化，避免只看单个赢家而忽略前沿更新 |

每轮返回 `selection_details`，结果返回 `initial_selection`、`final_selection`。记录每个候选的保留状态、原因、重复对象、前沿层级、拥挤度和边界状态，前端提供质量—模拟通信成本散点图及决策表。最终报告对应实际留下的种群；不会把历史上所有候选重新排名后冒充最终种群。

AST 去重是源码结构去重，并不证明语义等价或算法创新。拥挤度也不证明全局最优。本轮没有用盲测结果挑选赢家；通信成本仍使用当前模拟信道口径，不能据此宣称已完成真实射频硬件验证。

## 二、统一研究任务工作区

入口：`/#/workspaces`，总览主按钮可直接进入。工作区固定场景和任务类型；目前覆盖已有完整 Python 语义验证的六种任务。任务可归档和恢复，列表默认显示活动任务。

一次研究的关系为：

```text
研究任务
  → 配置版本（目标、父代、预设基线、模型元信息、开发集与评测计划）
  → 多次独立运行（预览 / 自优化 / 冻结验证 / 跨场景评测）
  → 冻结候选（初始父代、基线、演化赢家、其他已评估版本）
  → 运行结果、选择证据、评测报告与下载入口
```

主要行为：

1. 保存配置时登记初始候选，冻结 Task.py、配置 JSON 和源码摘要，保留全部配置版本。
2. 配置修改必须显式保存新版本才能运行；旧版本提交返回 409，同一任务有活动操作时不允许并发改配置或启动第二个操作。
3. 启动和排队执行前检查配置与初始源码。源码有变化时要求保存新版本，避免悄悄使用修改后的同名文件。
4. 每次演化分配独立前缀和运行 ID，复用现有模型生成、修复、沙箱、计量、预算与独立验证工作流。
5. 演化后登记所有已评估候选，并把赢家和基线关联回工作区。后续验证默认使用当前配置版本的最近成功赢家；没有赢家时使用预设基线。旧版本赢家不会被默用为新版本结果。
6. 跨场景评测默认比较赢家和预设基线，也可勾选候选；Python 评测自动补入预设基线，防止对照对象随勾选顺序变化。
7. 已有统计 JSON 候选可关联工作区，单独调度现有统计流水线。不同类型不能混排；JSON 每次选择一个版本和一组扰动。工作区目前的演化生成主链仍是 Python 协议。
8. SQLite 独立保留研究运行快照，即使普通后台任务历史超过 80 条被裁剪，工作区仍可恢复终态结果。停止操作沿用现有任务取消机制。
9. 服务重启后恢复历史状态，未完成任务标记中断；不会自动重新发送模型请求。该能力属于历史恢复，不是从中断轮次继续执行。
10. 模型连接可在工作区直接配置；仅保存模型地址、名称、温度、Token、超时及重试元信息。API Key 只在真实生成启动时提交，后台公开快照脱敏，不写入工作区配置或浏览器持久存储。

### 数据位置

- `code_add/course_project/outputs/workspaces/workspaces.sqlite3`：任务、版本、候选关联及运行快照。
- `outputs/workspaces/<任务ID>/revision_<版本>/`：冻结配置与 Task.py。
- 原有候选版本库、优化运行目录、独立评测目录继续保存执行证据，工作区保存关联关系。
- `ws_` 前缀的生成源码和 Prompt、数据库、构建及测试产物均作为运行数据忽略。

### HTTP 接口

| 方法与路径 | 功能 |
| --- | --- |
| GET `/api/workspaces` | 列出任务 |
| GET `/api/workspaces?id=...` | 任务、版本、候选及运行详情 |
| GET `/api/workspaces/export?id=...` | 下载研究记录 JSON |
| POST `/api/workspaces` | 创建任务 |
| POST `/api/workspaces/update` | 带 id、revision 保存新配置版本或归档状态 |
| POST `/api/workspaces/attach` | 关联已有冻结候选 |
| POST `/api/workspaces/run` | 运行 optimization、validation 或 evaluation |

运行请求返回 `{job, workspace_run_id}`，后续使用既有后台任务查询与停止接口。优化预览传 `preview: true`，不会调用模型。

## 三、验证

- Python 完整检查：`python -m tools.verify`，190 项测试通过，包含编译检查和临时目录 smoke 运行。
- 演化选择测试覆盖非支配关系、拥挤度、前沿门槛、结构去重、稳定决策、不可比数据拒绝和单唯一父代整轮演化。
- 工作区测试覆盖版本冲突、源码及配置篡改、排队后源码变化、密钥拒绝与脱敏、真实沙箱验证和小矩阵评测、离线替身生成的 Pareto 赢家流转、队列取消、历史裁剪、归档、重启恢复、JSON 分流和 HTTP 下载契约。
- 前端单元测试：9 项通过；TypeScript 检查和 Vite 生产构建通过。
- Playwright：15 项通过，覆盖 11 个页面、工作区保存与刷新恢复、配置版本、真实验证/评测和证据跳转、Pareto 决策展示、移动布局与已有功能回归。
- 格式检查使用 `npm run format:check`。

真实沙箱和小规模实验均已执行；模型生成整轮集成使用离线生成替身，没有自动请求付费模型，因此本轮测试不代表某个真实模型已经取得协议优化收益。已有公共组件和图表分包仍会出现 Vite 的 500 KB 构建提示，构建成功。
