## 2. 验证口径

### 2.1 五个阶段

1. **静态 AST**：解析源码，检查敏感标签属性、别名、内部反射和危险调用。
2. **导入/调用白名单**：限制模块来源；禁止任意导入、文件/系统相关危险调用及部分原生文件接口。
3. **运行时隔离**：严格模式通过标签代理拦截动态属性访问；通过审计钩子阻止文件打开、网络、子进程等操作。
4. **物理约束**：检查明确的 `bits_per_slot`、`frame_size` 是否为有限合法数值。兼容模式允许历史字段归一化，严格模式要求规范字段。
5. **任务语义**：使用任务注册表和评估侧真值，验证输出契约和任务结果。

静态门禁失败时不运行候选，后续阶段标记 `not_run`。源码在验证期间变化会导致失败。报告记录起始 seed、逐轮 seed、数据 hash、源码 hash、生成器 hash、完整验证参数与失败原因。

### 2.2 最终判定

| 判定 | 含义 |
| --- | --- |
| `passed` | 严格模式的结构、运行、物理和已有任务语义检查通过 |
| `warning` | 兼容模式通过已有检查，保留历史访问告警，不代表严格隔离通过 |
| `execution_only` | 执行和输出契约通过，但任务没有可计算的语义真值 |
| `failed` | 前置门禁、执行、物理约束、输出契约或已有任务语义失败 |

众数要求完整集合相等，返回真实众数的子集不会获得满分。均值、方差和基数使用评估侧真值；分位数采用线性插值。自定义任务没有统一真值时，`semantic_pass_rate=null`，页面显示输出契约通过率。缺失盘点缺少 `missing_ids`/`missing` 真值时同样标记语义未评估，不以标签总数冒充缺失真值。

### 2.3 资源和计时

- Web 验证默认每轮超时 15 秒；严格模式默认内存上限 768 MB。
- Windows 使用 Job Object 限制候选进程内存和活动进程数；POSIX 使用 `RLIMIT_AS`。
- 候选日志输出限制为 2 MB；父进程也检查子进程响应大小。
- 协议上报的时间保留在兼容字段中；另行记录 worker 内 `execute()` 的实测 CPU 和墙钟时间，不含进程启动时间。
- 模拟通信时间、候选自报时间、实测 CPU/墙钟时间分别解释，不能写成真实 RFID 硬件时延。

### 2.4 正式结果门禁

自由 Python 候选的通信计数属于 `candidate_self_reported`。即使严格验证通过，也不能只凭这些计数进入正式通信量 Pareto。需要使用现有统计协议通道的独立事件计数和相应任务契约。非法的负数、布尔值、小数和字符串计数会被拒绝，候选不能通过 metadata 覆盖系统给出的成本来源。

统计 JSON 候选经既有白名单编译器转换为受支持算子；失败的验证记录会作为负结果保留并排除出前沿。不存在的真实 LLM 候选保留 `missing_real_llm_candidate`，不以随机参数对照代替。

这些检查是软件验证。允许指定的标签响应辅助函数进行仿真读取，不构成密码学隐私证明，也不等于完整的操作系统沙箱。当前结果不宣称复现论文 PFG/DPFG 算法。

## 3. 实验身份和结果口径

`manifest.json` 是实验身份的权威记录，包含配置、TaskSpec、seeds、分布、规模、扰动、源码 hash、Python/依赖版本和产物 hash。`reproducibility_key` 排除运行 ID、输出目录和耗时等操作性字段。源码在实验执行期间变化时，实验不发布成功结果。

每个原始结果包含数据 hash、实际在场标签数、TaskSpec hash、候选标识和完整场景维度。失败行仍保留这些维度，避免从失败统计中丢失。

Pareto 在相同任务、分布、规模、值域、扰动、split、任务组合、seed 集合和数据 hash 下计算。执行失败、成本缺失、成本仅为候选自报、验证拒绝、误差不可用或 seed 重复都有明确排除原因。Web 直接读取后端判定，不在浏览器重新求前沿。选择多个场景时只做描述性汇总，不展示混合场景的前沿和置信区间。

误差均值区间使用独立 seed 的 Student-t 95% CI。少于两个独立 seed 时不提供该区间；小样本区间可能很宽，也可能超过指标的自然范围，不能据此声称稳定优势。P95 使用原始 seed 误差的排序统计量。Top-k 的图表误差为 `1-F1`，其他统计任务为相对误差。执行成功率与精度达标率分别统计。

`benchmark.audit` 检查文件完整性和复现标识一致性，不重新运行协议。旧 manifest 缺少 hash/key 时返回 `not_available`。SHA-256 是追溯和完整性证据，不是第三方签名或模型来源认证。

派生报告写入原始实验目录之外的独立目录；生成 `derived_manifest.json`，记录输入原始文件 hash 与输出产物 hash。重新绘图不会改动原始 manifest，也不会重跑协议或调用 LLM。

## 4. Web 操作

启动后访问 <http://127.0.0.1:8765>。

1. **验证沙箱**：选择协议、任务画像和严格/兼容模式，填写起始 seed，查看五阶段结果与验证历史。
2. **候选记录与父代谱系**：查看 `.candidate.json` 与统计候选记录中的父代引用、模型、Prompt/响应 hash、验证结果及源码一致性。没有记录的历史父代显示“无候选记录”，不会根据文件名推断关系。同名父代的多个记录保留歧义提示。
3. **统计基准**：按任务、分布、规模和扰动筛选；点击协议查看逐 seed 原始结果及失败原因。
4. **配置化复现实验**：填写 seeds、规模、分布、值域、任务画像、协议、扰动率和 split；后台保存配置并执行现有统计基准。
5. **实验历史与重建**：选择已保存实验，核对 TaskSpec、运行命令、源码和环境版本；点击“从原始结果重建报告”重新生成 CSV/JSON/PNG/PDF。

配置实验保存在 `Experiments/stat_protocols/config_runs/<run_id>/`，原始结果位于 `raw/`，派生报告位于 `derived/`。完整套件保存在独立 `runs/<run_id>/`，完成后才发布为页面的当前套件，避免读取半成品。

独立盲测应保留没有用于调参的数据。完整套件采用 `0–19` 和 `100–119`。配置页面的 validation/blind 会读取已归档、审计通过且带数据 hash 的参考结果，检查实际数据身份重叠；重叠、缺少参考集或缺少 hash 都不能通过。平台只能检查已记录的参考数据，不能证明未记录的历史使用。

页面另有“自动化验证与鲁棒性流水线”：冻结上方配置和协议参数，执行开发、验证、缺失、噪声、异常值、盲测六阶段，每阶段保留原始与派生报告，最后重复执行盲测核对确定性。可显式指定验证/盲测 seeds；留空时按开发 seeds 自动分配互不相交的组。缺失、噪声、异常阶段分别将对应扰动率提高到至少 0.1，其他输入保持冻结配置。

新生成的 Python 候选在场景 `outputs/protocol_traces/` 保存独立工作流和每次尝试的 Prompt、响应、源码、完整验证与诊断评价，后续修复不覆盖早期源码。页面展示修复次数与逐次证据审计。父代通过实际读取的源码 hash 和存在的候选 ID 解析；历史缺失记录不补造。诊断误差和 F1 复用现有评估器，通信仍为候选自报，不能据此进入正式通信 Pareto。统计候选仅在 ID、基因、Prompt/响应 hash 一致且归档审计通过时关联正式基准。

## 8. 本次修复的关键缺陷

1. AI 验证入口把 `RunResult` 当成另一种报告访问的问题，已统一使用共享验证服务。
2. 众数子集命中、缺失盘点误用标签总数、自定义任务误称准确率的问题，已按可用真值和输出契约区分。
3. 动态属性、代理内部属性、反射和原生文件接口的常见绕过，增加静态与运行时检查。
4. 候选 stdout 污染 JSON、无限输出、超量内存和异常退出，改为可保留的失败证据。
5. dashboard 未纳入 hash、配置未完整保存、跨场景前沿和缺少正式排除理由，已补齐追溯及后端汇总。
6. 候选自报成本冒充独立测量、非法通信计数被转换为合法整数、metadata 覆盖成本状态，已增加来源与类型约束。
7. 报告重建混入原始目录，以及移动端宽表挤压内容的问题，已分离派生产物并使用容器滚动。

后续可继续在这一工程边界内扩展已注册业务任务的真值和硬件数据入口；本次没有据此改写其他人的研究模块。
